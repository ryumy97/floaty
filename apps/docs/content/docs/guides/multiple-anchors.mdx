---
title: Multiple anchors
description: When there are multiple anchors, which one is the one that component will animate to?
---

## Choosing the active anchor

Any number of anchors can share a `floatyId`; 
but only one is active since we only render one Floaty component per id. 
It is the one with the highest `priority` (default `0`), and among equal priorities the most recently mounted one.
When it unmounts, the next one by the same rule becomes active, and changing `priority`
switches (and animates) to the new winner.

"Most recently mounted" follows React's layout-effect order:

- Anchors that mount together resolve by tree order: the later sibling wins, and a parent
  wins over an anchor nested inside it.
- An anchor whose `floatyId` changes, or that a React 19 `<Activity>` reveals, counts as
  newly mounted.

Set `priority` whenever two anchors can be mounted at once and the winner matters:

```tsx
<FloatyAnchor floatyId="player" priority={1} /> {/* detail view: always wins */}
<FloatyAnchor floatyId="player" />              {/* list item */}
```

## When active anchor is removed

What happens when the active anchor unmounts depends on whether another anchor takes its
place:

- **Other anchors are mounted:** the next one by the rules above becomes active right away,
  and the content animates to it.
- **It was the last anchor:** it stays active for a short grace period (`anchorGracePeriod`,
  default `150` ms), and the content stays where it is. If a new anchor mounts within that
  window, the content animates to it as if the two had swapped in one render. This covers
  anchors that mount a moment later: lazy routes, `Suspense` fallbacks, loading states and
  anchors rendered from an effect.
- **No anchor arrives in time:** the content hides. An anchor that mounts later makes it
  appear there without animating, since the old position is stale by then.

While hidden, the content stays mounted by default, keeping its React state, last size and
last [anchor state](/docs/guides/anchor-state). Use `keepMounted={false}` to unmount it
instead (see [Keeping content mounted](/docs/guides/keeping-content-mounted)).
`useFloaty(id).hasAnchor` tells you whether an anchor is active; it stays `true` during the
grace period.

If your loads regularly take longer than the grace period, raise it:

```tsx
configureFloaty({ anchorGracePeriod: 300 }); // 0 hides as soon as the last anchor unmounts
```

To make the content always fly somewhere instead of hiding, keep a low-priority anchor
mounted in a persistent layout, such as a mini-player in the app shell:

```tsx
// app shell: always mounted, used when nothing else is
<FloatyAnchor floatyId="player" priority={-1} />

// pages: take over while mounted, fly back to the shell when they unmount
<FloatyAnchor floatyId="player" />
```
