title: Anchor state
description: Let each layout tell the floating content how to render.
---

Each anchor can pass a `state` value to the floating content, so the same component can
render or behave differently per layout while keeping its own React state.

In the example below, the main area's anchor passes `{ color: '#4f46e5' }` and the
sidebar's passes `{ color: '#0d9488' }`. The counter reads it with `useFloatyState` and
turns indigo or teal depending on where it lands, while the count itself is kept:

There are three ways to read it:

- **`useFloatyState<S>()`** inside the content. It throws if called outside `<Floaty>`
  content.
- **Render-function children** get it as an argument:
  `<Floaty<PlayerState> floatyId="player">{(state) => <Player mode={state?.mode} />}</Floaty>`.
- **`useFloaty<S>(floatyId).state`** anywhere else.

## Switching form on landing

If a form only fits the destination box, switch it when the content lands instead of when it takes off. 
`useFloatyTransition<S>()` returns `{ state, settledState, isAnimating }`. 
`settledState` keeps the previous anchor's state for the whole transition 
and switches once the content lands (immediately if the move snaps).

The two hooks can also be combined so the timing depends on the direction.

The counter below shows "Clicked n times" in the main area and only the number in the small sidebar slot, 
and the full label never fits a box smaller than the main area:

- **To the sidebar** (`compact` false to true), it switches **at take-off**, reading
  `state`, so the label is already short while the box shrinks.
- **Back to the main area** (`compact` true to false), it switches **on landing**, reading
  `settledState`, so the label stays short until the box has grown.
