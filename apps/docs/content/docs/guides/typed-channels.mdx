---
title: Typed channels
description: Bind the components and hooks to one id and one state type.
---

With string ids, every call site picks its own state type, and a typo in an id silently
shows nothing. `createFloaty<S>(floatyId)` binds the components and hooks to one id and
types its anchor `state`. Call it once at module scope:

```tsx title="player.ts"
import { createFloaty } from '@floaty/react';

export const player = createFloaty<{ mode: 'full' | 'mini' }>('player');
```

```tsx title="App.tsx"
<player.Floaty>{(state) => <Player mode={state?.mode ?? 'full'} />}</player.Floaty>

<player.FloatyAnchor state={{ mode: 'mini' }} />
<player.FloatyAnchor state={{ mode: 'tiny' }} /> {/* type error */}
```

```tsx title="StatusBar.tsx"
function StatusBar() {
  const { hasAnchor, state } = player.useFloaty();
  return hasAnchor ? <span>{state?.mode}</span> : null;
}
```

The channel has `floatyId`, `Floaty`, `FloatyAnchor`, `useFloaty`, `useFloatyState` and
`useFloatyTransition`. They take the same props and return the same values as the unbound
API, without `floatyId`. They share the global store, so they mix freely with
`<Floaty floatyId="player">`. The bound `useFloatyState()` and `useFloatyTransition()` also
throw if called inside another id's content.

Keep using the unbound API for dynamic ids, such as one per list item.
