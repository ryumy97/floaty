Floaty lets React component **move between places in your layout without remounting**.
You can make a video keep playing, a form keep its input and a map keep its tiles, 
while the component moves from where it was to where it is now.

## The problem

In React, where a component sits in the tree decides its lifetime. 
Move it to a different parent and React unmounts the old instance and mounts a new one:

```tsx
{isMini ? (
  <Sidebar>
    <VideoPlayer /> {/* a new player: playback restarts, buffering starts over */}
  </Sidebar>
) : (
  <Grid>
    <VideoPlayer />
  </Grid>
)}
```

In many cases, you want to keep the component live and visible, 
then move and fit to new locations when the layout changes.

## How it works

Floaty components separate **what** is rendered from **where** it appears:

- `<Floaty>` renders your component **once**, in a layer on top of the page. Put it
  somewhere that never unmounts, like your app shell, and its state survives every layout
  change.
- `<FloatyAnchor>` is an empty placeholder you put in your layouts. It reserves the space,
  and the floating component is drawn exactly over whichever anchor is on screen.

When the active anchor changes, the component springs from the old spot to the new one.

- **State that survives layout changes**, including across page navigations in Next.js.
- **Smooth transitions** with springs or easing, interruptible mid-flight, and skipped for
  users who prefer reduced motion.
- **Per-place variations** through anchor `state`: the same player can show full controls
  in the grid and compact ones in the sidebar.
- **Native scroll performance**: floating content moves with the page in the same frame.
